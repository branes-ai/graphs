# Changelog 2026-05-21

Two-day arc spanning 2026-05-20 → 2026-05-21 that **closes the
PhysicalSpec backfill campaign** opened by `#130` in early-May. Across
two sessions, three cross-repo sprints landed and three umbrella
issues closed: `#130` (foundation + initial backfill) at 79%, then
the long-tail follow-up `#241` at the ceiling of **43/47 (91%)**
where every catalog entry with public die data is now populated.

The four surviving N/A entries are bounded by data availability, not
engineering effort:
- ARM-Mali-G78 / Qualcomm-Snapdragon-Ride (no public die data)
- AmpereOne 1-core ref / Stillwater DFM-128 (synthetic / research)

Cumulative trajectory: **9/47 (19%) → 43/47 (91%)** across the
campaign.

Landed via 7 merged graphs PRs and 14 merged embodied-schemas PRs
across the three sprints. graphs: +486 / -90 LOC. embodied-schemas:
+6,637 / -100 LOC (most of the bulk is the 14 SKU YAMLs + their
parity tests).

## Fixed

- **KPU PhysicalSpec regression** in
  `graphs/src/graphs/hardware/mappers/accelerators/kpu.py`
  (`graphs#236`). 4 KPU factories called
  `load_physical_spec_or_none` (legacy `data/kpus/` path) but the
  KPU SKU YAMLs had moved to `data/compute_products/stillwater/`
  during the ComputeProduct unification (around
  `embodied-schemas#156`/`#168`), causing silent fallback to
  `physical_spec=None`. Switched to
  `load_physical_spec_from_compute_product_or_none`. Restored
  KPU coverage 0/4 → 4/4.
- **Intel Xeon 8592+ memory bandwidth** in
  `graphs/src/graphs/hardware/models/datacenter/
  intel_xeon_platinum_8592plus.py` (`graphs#240`). Factory had
  inherited DDR5-4800 (307.2 GB/s) from the 8490H model, but
  Intel's published spec for the 8592+ is DDR5-5600 (358.4 GB/s).
  Corrected; affects memory-bound regions of roofline analysis on
  the 8592+ only. No test regressions across the full hardware
  suite.
- **`test_unpopulated_factory_returns_none_physical_spec`** and 4
  CLI tests (`graphs#238`, `#243`). The unpopulated-control SKU
  rotation as backfills consumed prior controls: A100 → T4 → ARM
  Mali-G78. The history is preserved as inline comments documenting
  the rotation.

## Infrastructure

- **Cross-repo work pattern established**: one ComputeProduct YAML
  per PR in `embodied-schemas`, followed by a downstream wiring PR
  in `graphs`. 14 SKU PRs + 2 process-node additions on the data
  side, then bundled wiring PRs on the consumer side (one per
  sprint). Mirrors the DSP-batch pattern from `#211`/`#223`.
- **Single-virtual-die approximation** for chiplet products. All
  multi-die SKUs (EPYC 9654/9754/9965, Xeon 8490H/8592+/6980P) use
  a single virtual die with `silicon_bin` decomposing across
  chiplets, because the schema's `AnyBlock` discriminated union
  lacks an `IOBlock` kind for the IOD. Documented in each YAML's
  header + flagged for re-author once an IOBlock kind lands
  (deferred to a future schema sprint).
- **Schema enum values exercised for the first time**:
  `CPUISAExtension.AMX_TILE / AMX_BF16 / AMX_INT8 / AMX_FP16` --
  declared in v3 schema but unused until the Xeon entries.
  `TPUFabricKind.TPU_V1_STYLE` -- declared in v7 schema but
  unused until the TPU v1 entry.
- **Multi-fabric `CoreClusterSpec.compute_fabrics`** -- the
  schema's `min_length=1` field has supported multiple fabrics
  per cluster since v3, but no SKU exercised it until the Xeon
  8490H YAML added a homogeneous cluster with both AVX-512 and
  AMX fabrics simultaneously. All 3 Xeon entries now use this
  multi-fabric layout.
